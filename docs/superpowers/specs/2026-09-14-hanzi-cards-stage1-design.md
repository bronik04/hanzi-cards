# Карточки 汉字 — Этап 1: библиотека колод

Дата: 2026-09-14
Статус: утверждён
Предшественник: [2026-09-12-hanzi-cards-stage0-design.md](2026-09-12-hanzi-cards-stage0-design.md)

## Контекст

Этап 0 закрыт: приложение переехало на React + TypeScript + Vite, карточка
получила три поля, появился выбор направления, приложение опубликовано и
работает без сети. Осталось ограничение, ради которого этап 1 и затевался:
колода ровно одна. Каждый урок таблицу нужно вставлять заново, а прошлая
пропадает.

Этот документ описывает только Этап 1.

## Цель этапа

Колод становится много. У каждой своё имя и своя прерванная тренировка.
Библиотека целиком выгружается в файл и загружается обратно, отдельная
колода — выгружается таблицей.

## Состав

Входит:

- библиотека: создание, открытие, переименование, удаление колод;
- у каждой колоды собственная прерванная тренировка, направление и счётчики;
- перенос единственной колоды из формата Этапа 0;
- выгрузка и загрузка всей библиотеки одним файлом JSON;
- выгрузка отдельной колоды таблицей и загрузка таблицы как новой колоды.

Отложено осознанно:

- **редактор карточек.** Опечатка чинится выгрузкой колоды таблицей, правкой
  в редакторе таблиц и загрузкой обратно. Отдельный этап, когда станет ясно,
  что этого мало.
- **папки и темы.** Имеют смысл, когда колод десятки; на пяти-десяти
  плоский список с сортировкой по недавности удобнее.

## Что колода помнит

Только прерванную тренировку. Закончил — следующая начинается с нуля.
Накопленная история по карточкам и списки трудных слов в этот этап не входят.

## Модель данных

`direction`, `session`, `stats` и `startedMode` переезжают из корня состояния
внутрь колоды. Сейчас они лежат рядом с `cards`, потому что колода одна.

```ts
type Deck = {
  id: string;
  name: string;
  createdAt: string;      // ISO
  lastOpenedAt: string;   // ISO, по нему сортируется список
  cards: Card[];
  direction: Direction;
  session: Session | null;
  stats: Stats;
  startedMode: SessionMode;
};

type StoredState = {
  version: 3;
  decks: Deck[];
  activeDeckId: string | null;
};
```

`Card`, `Direction`, `Session`, `Stats` и `SessionMode` не меняются.

## Хранение

Вся библиотека лежит под одним ключом `flashcards.v3`: одна проверка при
чтении, одна атомарная запись, ни одного состояния, где индекс ссылается на
несуществующую колоду.

Плата — каждый свайп переписывает библиотеку целиком. Замеры сериализации:

| Библиотека | Размер | Время |
|------------|--------|-------|
| 5 колод × 100 карточек | 58 КБ | 0,17 мс |
| 10 × 200 | 230 КБ | 0,60 мс |
| 20 × 300 | 691 КБ | 4,2 мс |
| 50 × 300 | 1728 КБ | 8,4 мс |

При лимите localStorage около 5 МБ реалистичные для преподавателя 10–30 колод
дают доли миллисекунды. Разделение на ключ-на-колоду остаётся запасным ходом:
оно целиком помещается внутрь `core/storage.ts` и снаружи незаметно.

### Перенос из формата Этапа 0

При первом запуске, если ключа `flashcards.v3` нет, читается `flashcards.v2`.
Единственная колода оборачивается в `Deck`: имя — «Колода от Д месяца ГГГГ» по
дате переноса, `cards`, `direction`, `session`, `stats` и `startedMode`
переносятся как есть, `activeDeckId` указывает на неё. Результат сразу
записывается под новым ключом.

Ключ `flashcards.v2` не удаляется и не изменяется — он остаётся запасной копией
на случай, если перенос окажется неверным.

Это отличается от Этапа 0, где перенос из `flashcards.state.v1` был отвергнут:
там был прототип, которым никто не пользовался. Формат v2 развёрнут и в работе,
и терять колоду недопустимо.

## Состояние приложения

```ts
type Screen = 'library' | 'import' | 'resume' | 'mode' | 'training' | 'done';

type AppState = {
  decks: Deck[];
  activeDeckId: string | null;
  screen: Screen;
  hydrated: boolean;
  storageFailed: boolean;
  storageUnreadable: boolean;
};
```

Доступ к текущей колоде — через селектор `activeDeck(state): Deck | null`.
Экраны тренировки, режима, возобновления и итогов читают колоду через него и
больше не знают о существовании библиотеки.

Действия редьюсера:

| Действие | Что делает |
|----------|-----------|
| `restore`, `hydration-finished`, `storage-failed` | как в Этапе 0 |
| `storage-unreadable` | хранилище есть, но не читается: запись выключается, чтобы не затереть его |
| `deck-created { name, cards }` | добавляет колоду, делает её активной, ведёт на выбор режима |
| `deck-opened { id }` | делает колоду активной, обновляет `lastOpenedAt`, ведёт на возобновление или выбор режима |
| `deck-renamed { id, name }` | меняет имя |
| `deck-deleted { id }` | удаляет колоду вместе с её сессией |
| `decks-imported { decks }` | сливает колоды из файла с существующими; слияние живёт в редьюсере, а не в обработчике, иначе правка библиотеки во время чтения файла откатывалась бы |
| `go-to-library` | возврат в библиотеку |
| `go-to-import` | как в Этапе 0. Обратно — общей кнопкой «В библиотеку», без отдельного действия отмены |
| `direction-changed`, `session-started`, `swiped`, `resume-confirmed`, `go-to-mode` | работают с активной колодой |

Действия, требующие активной колоды, при `activeDeckId === null` возвращают
состояние без изменений.

## Экраны

### Библиотека

Новый экран. Список колод, сверху недавно открытые. В строке — имя, число
карточек и пометка «тренировка не закончена», если у колоды есть незавершённая
сессия. Действия строки: открыть, переименовать, выгрузить таблицей, удалить.

Переименование правится прямо в строке. Удаление требует подтверждения там же,
тем же приёмом, что уже работает на экране возобновления: кнопка сменяется
вопросом с вариантами «Удалить» и «Отмена».

Над списком: «Добавить колоду», «Сохранить библиотеку в файл», «Загрузить
библиотеку из файла».

### Импорт

К экрану Этапа 0 добавляется поле имени. Подсказка подставляется заранее: имя
файла без расширения, если колоду грузят файлом, иначе дата. Поле можно
очистить — тогда используется подсказка.

«В библиотеку» возвращает в библиотеку всегда, а не только когда колоды уже
есть. Условный выход запирал пустую библиотеку: «Загрузить библиотеку из
файла» живёт на экране библиотеки, и после чистки браузера — ровно тогда,
когда файл и нужен, — попасть туда было бы неоткуда.

### Возобновление, выбор режима, тренировка

Источник данных меняется: колода берётся селектором. Выход из тренировки
по-прежнему требует подтверждения и бросает сессию, возвращая на выбор режима
той же колоды.

Кроме того, на каждом из трёх экранов есть «В библиотеку», сохраняющая
прерванную тренировку. Без неё сценарий приёмки «начать тренировку в первой
колоде, вернуться в библиотеку, открыть вторую» выполнялся бы только через
экран импорта с последующей отменой, а единственный прямой выход — «Выйти» —
сессию бросает.

С экрана возобновления снято предупреждение «Прогресс текущей тренировки будет
потерян»: в библиотеке новая колода добавляется к существующим и чужую сессию
не трогает.

### Итоги

Кнопки становятся «Начать заново» и «В библиотеку». Выбор режима убран из этой
развилки: он в одном клике из библиотеки, а третья кнопка стоит дороже, чем
экономит.

### Поток

Запуск: колод нет — импорт, колоды есть — библиотека. Открытие колоды: есть
незавершённая сессия — возобновление, нет — выбор режима.

Правило про пустую библиотеку действует только в момент чтения хранилища. Дальше
экран хранится в состоянии и меняется только действиями, поэтому удаление
последней колоды оставляет пользователя в библиотеке, а не выбрасывает на импорт.

## Выгрузка и загрузка

Текст файлов готовит `core`, сохранение файла делает слой представления:
`core` не имеет доступа к DOM, и это правило Этапа 0 остаётся в силе.

### Библиотека целиком

Формат — тот же JSON, что и в хранилище, без `activeDeckId`:
`{ version: 3, decks: [...] }`. Имя файла `hanzi-cards-ГГГГ-ММ-ДД.json`.

Загрузка **добавляет** колоды к существующим и никогда не заменяет библиотеку.
Один и тот же файл, загруженный дважды, даёт два комплекта колод — это
предсказуемее, чем молчаливая замена, и не уничтожает то, что уже есть.
Восстановление после чистки браузера работает так же: библиотека пуста,
добавление к пустому и есть восстановление.

Разрешение конфликтов при загрузке:

- совпал идентификатор колоды — новой колоде выдаётся новый;
- совпало имя — к имени добавляется « (2)», при необходимости « (3)» и дальше;
- идентификаторы карточек сохраняются как есть: они UUID, и ссылки сессии
  на них должны продолжать работать;
- сессия колоды ссылается на отсутствующую карточку — сбрасывается только
  сессия, колода загружается. Это мягче, чем проверка хранилища, которая в
  таком случае отвергает состояние целиком: файл приходит от пользователя, и
  терять из-за одной битой сессии всю колоду неправильно.

Файл, который не разбирается как JSON или не проходит проверку структуры,
отклоняется с сообщением; библиотека не меняется.

### Отдельная колода

Формат — таблица с разделителем-табуляцией и строкой заголовка
`иероглиф	пиньинь	перевод`. Именно табуляция, а не запятая: переводы часто
содержат запятые, а существующий разбор предпочитает табуляцию и распознаёт
этот заголовок. Имя файла — имя колоды с расширением `.tsv`, где символы `/ \ : * ? " < > |`
и управляющие заменены на дефис, пробелы по краям убраны; если после этого
ничего не осталось, используется `deck`.

Табуляции и переводы строк внутри полей заменяются на пробел: в формате с
разделителем-табуляцией они разорвали бы строку, а поле, которое ломает
собственный формат, хуже поля, потерявшего один пробельный символ.

Прогресс в таблицу не попадает. Загрузка такой таблицы на экране импорта
создаёт новую колоду — отдельного пути для неё не нужно.

## Обработка ошибок

Запись не удалась — работает механизм Этапа 0: приложение продолжает работать
в памяти и один раз показывает предупреждение. Текст дополняется подсказкой
сохранить библиотеку в файл: при переполнении квоты это единственный способ не
потерять колоды.

Битый файл при загрузке библиотеки — сообщение об ошибке на экране библиотеки,
состояние не меняется.

Удаление последней колоды оставляет пустую библиотеку с предложением добавить
первую, а не выбрасывает на экран импорта: пустой список — нормальное
состояние, а не ошибка.

## Тестирование

**Vitest, слой `core`:**

- операции над библиотекой: добавление, переименование, удаление, поиск по
  идентификатору, сортировка по недавности;
- перенос из v2: колода, сессия, счётчики и направление сохраняются; отсутствие
  v2 даёт пустую библиотеку;
- проверка хранилища v3: битый JSON, чужая версия, колода без обязательного
  поля, сессия со ссылкой на отсутствующую карточку;
- выгрузка библиотеки и загрузка обратно дают ту же библиотеку;
- конфликты при загрузке: совпадение идентификатора, совпадение имени
  однократное и многократное, битая сессия внутри годной колоды;
- выгрузка колоды таблицей: заголовок, разделитель, экранирование переводов
  с табуляцией внутри; результат разбирается обратно существующим `parseTable`.

**Редьюсер:**

- создание колоды делает её активной и ведёт на выбор режима;
- открытие колоды с незавершённой сессией ведёт на возобновление, без неё —
  на выбор режима;
- тренировка в одной колоде не трогает сессию другой;
- удаление активной колоды сбрасывает `activeDeckId`;
- действия, требующие активной колоды, при её отсутствии не меняют состояние.

**React Testing Library:**

- библиотека показывает имена, число карточек и пометку незавершённой
  тренировки;
- переименование в строке меняет имя;
- удаление требует подтверждения, отмена оставляет колоду на месте;
- экран импорта подставляет имя-подсказку и принимает введённое.

**Playwright:**

- создать две колоды, начать тренировку в первой, вернуться в библиотеку,
  открыть вторую, вернуться в первую и обнаружить прерванную тренировку на том
  же месте;
- выгрузить библиотеку в файл и загрузить его обратно.

## Макеты перед реализацией

Экраны показываются до начала работы над кодом и утверждаются отдельно.
Макеты собираются на настоящих стилях проекта — `src/styles/tokens.css` и
`src/styles/app.css`, — чтобы показывать реальные шрифты, цвета и размеры, а не
приблизительные. Реализация не начинается, пока макеты не одобрены.

## Вне рамок

- редактор карточек;
- папки, темы, теги, поиск по библиотеке;
- накопленная история по карточкам, интервальное повторение, статистика;
- тест с вариантами, подбор пар, ввод с клавиатуры, аудирование — Этап 2;
- проектор, команды, счёт, таймер — Этап 3;
- бэкенд и ученики — Этап 4;
- синхронизация между устройствами: перенос делается файлом вручную.

## Критерии готовности

1. Создаются несколько колод, у каждой своё имя.
2. Переключение между колодами не теряет прерванную тренировку ни в одной.
3. Колода из формата Этапа 0 переносится в библиотеку при первом запуске,
   вместе с сессией и счётчиками.
4. Библиотека выгружается в файл и загружается обратно без потерь, включая
   прерванные тренировки.
5. Повторная загрузка того же файла добавляет колоды, а не заменяет их, и
   разводит совпавшие имена.
6. Отдельная колода выгружается таблицей, и эта таблица загружается обратно
   существующим экраном импорта.
7. Переименование и удаление работают; удаление требует подтверждения.
8. `src/core` не содержит импортов React и обращений к `window` и `document`.
9. `lint`, `typecheck`, `test`, `build` и сквозные тесты проходят в CI.
10. Макеты экранов показаны и одобрены до начала реализации.
