# Карточки 汉字, Этап 2a — язык интерфейса

Предшественник: [2026-09-14-hanzi-cards-stage1-design.md](2026-09-14-hanzi-cards-stage1-design.md)

## Контекст

Этапы 0 и 1 собрали работающее приложение: библиотека колод, два режима
тренировки, обмен файлами, офлайн. Внешний вид при этом рос по месту. В
`src/styles/app.css` 544 строки, радиус и тени заданы россыпью, а правил
`:focus` нет ни одного — с клавиатуры приложение проходится вслепую.

Этап 2 по исходной разбивке — новые режимы тренировки: тест, подбор пар, ввод
с клавиатуры, аудирование. Их четыре, и каждый добавляет экран. Оформлять
девять экранов дороже, чем пять, и переделывать новые сразу после написания —
работа впустую. Поэтому Этап 2 разделён надвое, и этот документ описывает
первую половину.

| Этап | Содержание | Статус |
|------|-----------|--------|
| 0 | Фундамент: React + TS + Vite, китайская модель карточки, PWA, CI | готов |
| 1 | Библиотека колод, обмен файлами | готов |
| **2a** | **Язык интерфейса: типографика, сетка, состояния, движение** | **этот спек** |
| 2b | Режимы тренировки: тест, подбор пар, ввод с клавиатуры, аудирование | позже |
| 3 | Классный режим: проектор, команды, счёт, таймер | позже |
| 4 | Бэкенд, аккаунты, ученики занимаются дома | позже |

**Аудитория прежняя** — преподаватель китайского языка, который ведёт урок с
ноутбука через проектор. Это определяет решения, которые иначе выглядели бы
произвольными: тёмный фон, приглушённые цвета, крупный шрифт.

**Ориентир — Quizlet.** У него взяты ритм, скругления, тени, цветовая
идентичность режимов и характер движения. Не взят светлый фон: Quizlet рисуют
для ноутбука на расстоянии вытянутой руки, где белое не слепит. На стене класса
всё наоборот, и в спеке Этапа 0 тёмная тема записана как решение, а светлая —
как не планируемая.

## Цель этапа

Пять существующих экранов получают связный язык: единые шкалы, состояния,
движение, переходы. **Новой функциональности ноль.** Ни одного нового режима,
ни одной кнопки, которая делает что-то, чего приложение не делало вчера.

Единственный новый компонент — меню действий над колодой, и оно заменяет уже
существующие кнопки, а не добавляет возможность.

## Дизайн-токены

Палитра из Этапа 0 не меняется: `--bg: #0a092d`, `--surface: #2e3856`,
`--surface-raised: #3a4a6b`, `--text: #f6f7fb`, `--text-muted: #a0a8c0`,
`--accent: #4255ff`, `--yes: #3ccf91`, `--no: #ff5a5f`.

Добавляются шкалы, которых сейчас нет.

**Скругления.** `--radius-sm: 8px`, `--radius-md: 12px`, `--radius-lg: 16px`,
`--radius-pill: 999px`. Нынешний `--radius: 16px` становится `--radius-lg`;
хардкод `8px` и `3px` по файлу заменяется на шкалу.

**Тени.** `--shadow-sm: 0 4px 14px rgb(0 0 0 / 0.25)`,
`--shadow-md: 0 8px 22px rgb(0 0 0 / 0.35)`,
`--shadow-lg: 0 12px 32px rgb(0 0 0 / 0.45)`. Карточка колоды — `sm`, плитка
режима и карточка тренировки — `md`, всплывающее меню — `lg`.

**Отступы.** `--space-1: 0.25rem` … `--space-6: 2rem` (4, 8, 12, 16, 24, 32
пикселей). Нынешний `--gap: 1rem` остаётся синонимом `--space-4`.

**Веса шрифта.** `--weight-regular: 400`, `--weight-semibold: 600`,
`--weight-bold: 700`, `--weight-heavy: 800`. Заголовки экранов — `bold`,
названия плиток и колод — `bold`, число на кольце итогов — `heavy`.

**Кольцо фокуса.** `--focus-ring: 0 0 0 3px #4255ff80`. Применяется через
`:focus-visible` ко всем интерактивным элементам. Это не косметика: сейчас
правил `:focus` в `app.css` ноль, и человек, идущий табом, не видит, где он.

Цвета режимов задаются здесь же, потому что на Этапе 2b их станет шесть:
`--mode-simple: var(--accent)`, `--mode-ring: #f0b429`. Плитка с жёлтым фоном
берёт тёмный текст `#26210a` — белый по жёлтому не проходит по контрасту.

## Экраны

### Библиотека

Строки во всю ширину заменяются сеткой карточек. Точки перелома совпадают с
единственной существующей в проекте (`max-width: 40rem`) и добавляют одну:
три колонки шире `55rem`, две от `40rem` до `55rem`, одна уже `40rem`.

Карточка колоды содержит название, число карточек и — если тренировка не
закончена — метку с точкой цвета акцента. Действия убраны под кнопку «⋯» в
правом верхнем углу.

**Меню действий — единственный новый компонент этапа, и он делается целиком.**
Открывается по клику и по Enter/Space, забирает фокус на первый пункт,
закрывается по Escape, по клику мимо и по выбору пункта, ходит стрелками вверх
и вниз, а после закрытия возвращает фокус на кнопку «⋯». Пункты: «Переименовать»,
«Выгрузить таблицей», «Удалить» — последний цветом `--no`.

Переименование и подтверждение удаления остаются такими же, как на Этапе 1:
поле с «Сохранить» и «отмена», подтверждение с фокусом на «отмена». Меняется
только оформление.

Панель сверху — «Добавить колоду» основной кнопкой, «Сохранить в файл» и
«Загрузить из файла» приглушёнными. Правило Этапа 1 сохраняется: «Сохранить в
файл» не показывается при пустой библиотеке.

### Выбор режима

Радиокнопки направления в рамке заменяются чипами: три компактные таблетки в
строку, выбранная подсвечена акцентом. Чип «иероглиф → пиньинь» недоступен,
если в колоде нет пиньиня, — правило прежнее, меняется подача.

Режимы становятся плитками в два столбца: «Просмотр» цвета `--mode-simple`,
«Кольца по 7» цвета `--mode-ring`. У каждой плитки название, короткое пояснение
(«Один круг, без повторов» и «Блоками, до полного круга») и схематичное превью.

**Плиток ровно две.** Заглушки для режимов Этапа 2b не показываются: обещать
то, чего нет, хуже, чем не обещать ничего.

Ссылки «В библиотеку» и «Загрузить новую таблицу» остаются.

### Тренировка

Структура не меняется — это единственный экран, обкатанный на уроках, и менять
его вслепую рискованно. Меняется оформление и обратная связь.

**Шапка.** Прогресс уже существует: `SimpleProgress` рисует полосу, а
`RingProgress` — сегменты по блокам, и оба рендерятся под шапкой. Полоса
поднимается в строку шапки, между кнопкой закрытия и подписью стадии, чтобы
шапка читалась одной строкой; сегменты режима колец остаются отдельной строкой —
их восемь, в строку шапки они не помещаются. Подпись стадии остаётся дословно
(«Блок 2 из 4 · осталось 5»).

**Счётчики.** Сейчас это таблетки с нейтральным фоном `--surface` и цветным
текстом. Фон становится цветным с низкой непрозрачностью, добавляются значки:
`✕ 3` и `✓ 9`. Отличие с расстояния перестаёт держаться на одном оттенке текста.

**Подкраска по ходу свайпа.** Контур уже есть, но включается ступенькой:
`Card.tsx` вешает `card--yes` / `card--no` при смещении больше
`TINT_THRESHOLD` (20 пикселей), и цвет появляется скачком на полную яркость.

Меняется на непрерывное: непрозрачность контура растёт линейно от нуля до
единицы на протяжении `SWIPE_THRESHOLD` (80 пикселей,
`src/hooks/useSwipeGesture.ts`), то есть достигает максимума ровно тогда, когда
отпускание засчитает свайп. К контуру добавляются лёгкая заливка (`#3ccf9124`
и `#ff5a5f24`) и штамп «ЗНАЮ» или «СНОВА» с той же непрозрачностью.

`TINT_THRESHOLD` исчезает: ступенька была приближением к непрерывности, и
держать обе не нужно. Поворот карточки (`rotate(offset / 20)`) и отъезд
(`EXIT_DISTANCE`) остаются как есть.

Громкость выбрана намеренно приглушённой: у проектора контраст хуже, чем у
монитора, и то, что на ноутбуке выглядит спокойно, на стене слепит.

**Кнопки «Изучать снова» и «Знаю»** получают цвета `--no` и `--yes`
приглушённой заливкой: текст цвета `--no` или `--yes`, фон того же цвета с
непрозрачностью `2e` (18%), рамка с непрозрачностью `6b` (42%). Сплошной
заливки нет. Сейчас обе синие и с расстояния неразличимы. После покраски
кнопка и жест говорят на одном языке: зелёное справа значит одно и то же,
тянешь ты карточку или жмёшь кнопку.

### Итоги

Кольцо прогресса с процентом крупно в центре, под ним счётчики таблетками, под
ними кнопки «Начать заново» и «В библиотеку».

Процент — главное число, количество — вспомогательное. Кольцо и оба счётчика
набегают за 1,4 секунды: за это время видно не только результат, но и как он
набрался.

### Импорт и возобновление

Структура и поведение не меняются. Применяются токены: типографика, кнопки,
отступы, кольцо фокуса.

## Движение

**Уровень.** Обратная связь и состояния, переходы между экранами, анимация
итогов. Праздничных моментов — конфетти, звука, встряхивания при ошибке — нет:
на уроке это секунды, которых нет, и шум в классе.

**Переходы между экранами — вручную на CSS**, а не через View Transitions API.
Работают одинаково во всех браузерах. Направление несёт смысл: вглубь (открытие
колоды, старт тренировки) новый экран приходит справа, старый отъезжает влево и
гаснет; назад — зеркально. Длительность 340 мс, кривая
`cubic-bezier(.3,.7,.3,1)`.

Два требования, без которых такой подход ломается, и оба проверяются тестами.

**Фокус при подмене.** Пока старый экран ещё в DOM, фокус не должен оставаться
на исчезающей кнопке. После завершения перехода фокус уходит на заголовок
нового экрана.

**Анимация не блокирует ввод.** Два быстрых нажатия «Знаю» подряд, быстрее
длительности анимации, учитываются оба. Уход с экрана во время анимации
свайпа не теряет свайп. Это ровно та ошибка, которую поймало сквозное ревью
Этапа 1.

**`prefers-reduced-motion`** отключает перемещения, масштабирования и переходы
между экранами: смена становится мгновенной. Блок в `app.css` уже есть, но
покрывает одну лишь `.card` — он расширяется на всё движение этапа. Подкраска при свайпе, цвет
счётчиков и состояния кнопок остаются — это информация, а не украшение.
Набегание чисел на итогах заменяется готовым значением.

## Архитектура

Слои Этапа 0 не меняются: `src/core` остаётся чистым, `src/state` держит
состояние, экраны читают колоду через `useActiveDeck`.

Существующее переиспользуется, а не пишется заново: `SimpleProgress`,
`RingProgress`, `Counters`, `Card` и `useSwipeGesture` остаются на месте, у них
меняется оформление и — у `Card` — расчёт непрозрачности.

Новое появляется в двух местах.

`src/components/DeckMenu.tsx` — меню действий: клавиатура, фокус, закрытие. Один
компонент с понятным интерфейсом (`items`, `onSelect`, `label`), который можно
проверить отдельно от библиотеки.

`src/hooks/useReducedMotion.ts` — чтение `prefers-reduced-motion` через
`matchMedia` с подпиской на изменение. Хук, а не проверка по месту: иначе
одно и то же условие расползётся по пяти экранам.

Переход между экранами реализуется в `src/App.tsx`, где уже происходит разбор
`screen`. Направление вычисляется из пары «предыдущий экран → текущий»: список
переходов «вглубь» задаётся явной таблицей, всё остальное считается возвратом.
Явная таблица, а не эвристика по индексу экрана: экранов шесть, порядок между
ними не линейный, и угадывание здесь читалось бы хуже, чем перечисление.

`src/styles/app.css` разделяется по ответственности. 544 строки в одном файле
уже сейчас неудобны, а этап добавит к ним сетку библиотеки, плитки, меню и
переходы. Разделение: `tokens.css` (шкалы), `base.css` (сброс, типографика,
фокус), `components.css` (кнопки, таблетки, карточки, меню), `screens.css`
(то, что относится к конкретным экранам).

## Проверка

«Стало красивее» тестом не покрывается, поэтому критерий сформулирован иначе:
**ни один существующий сценарий не сломался, а всё новое поведение покрыто как
поведение.**

**Регрессии.** 295 модульных и 13 сквозных тестов — страховка. Часть придётся
поправить: меняются разметка и надписи. **Правка селектора не должна ослаблять
проверку.** Это правило записано прямо, потому что на Этапе 1 замена файла
теста целиком дважды молча выкинула покрытие — сначала два теста режима колец,
потом проверку `startedMode`. Каждая правка теста в этом этапе сопровождается
ответом на вопрос: что этот тест доказывал раньше и доказывает ли он это
теперь.

**Новое поведение.**

- меню: открытие с клавиатуры, фокус на первом пункте, Escape, клик мимо,
  стрелки, возврат фокуса на кнопку;
- фокус после перехода между экранами уходит на заголовок нового экрана;
- два быстрых нажатия «Знаю» подряд дают два засчитанных ответа;
- уход с экрана тренировки во время анимации свайпа не теряет свайп;
- при `prefers-reduced-motion` переходы и набегание чисел не запускаются, а
  подкраска при свайпе работает.

**Вручную.** На проекторе в классе: читается ли подкраска с задней парты и не
слепит ли. Это единственная проверка, которую нельзя автоматизировать, и её
делает преподаватель.

## Вне рамок

- новые режимы тренировки и озвучка — Этап 2b;
- редактор карточек — этап не назначен;
- светлая тема и переключатель — не планируется, решение Этапа 0;
- визуальное регрессионное тестирование скриншотами — дорого держать, ломается
  от смены версии браузера;
- анимированные иллюстрации и превью внутри плиток сложнее схематичных;
- папки, темы, теги, поиск по библиотеке — этап не назначен.

## Критерии готовности

1. Библиотека — сетка карточек; действия открываются меню «⋯», которое
   полностью управляется с клавиатуры и возвращает фокус.
2. Выбор режима — две цветные плитки и чипы направления; заглушек будущих
   режимов нет.
3. На экране тренировки при свайпе видно, что произойдёт, до отпускания.
4. Кнопки «Изучать снова» и «Знаю» различимы по цвету.
5. Итоги показывают кольцо с процентом, значения набегают.
6. У всех интерактивных элементов есть видимое кольцо фокуса.
7. Переходы между экранами направленные; фокус после перехода на заголовке.
8. При `prefers-reduced-motion` движения нет, информация цветом осталась.
9. Все существующие тесты зелёные, ни одна проверка не ослаблена.
10. `npm run test`, `npm run lint`, `npm run typecheck`, оба стенда Playwright
    и `npm run build` — чисто.
