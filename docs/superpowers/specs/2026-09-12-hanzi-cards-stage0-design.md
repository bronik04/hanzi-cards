# Карточки 汉字 — Этап 0: фундамент

Дата: 2026-09-12
Статус: утверждён
Предшественник: [2026-09-09-flashcards-design.md](2026-09-09-flashcards-design.md)

## Контекст

Существующее приложение — прототип: один самодостаточный HTML-файл на vanilla JS,
одна колода, два поля на карточке, состояние в localStorage. Оно работает, но
упирается в потолок: добавить библиотеку колод, новые режимы тренировки и работу
с классом поверх 440 строк императивной работы с DOM невозможно без переписывания
слоя представления.

Проект развивается в четыре этапа. Этот документ описывает только Этап 0.

| Этап | Содержание | Статус |
|------|-----------|--------|
| 0 | Фундамент: React + TS + Vite, китайская модель карточки, PWA, CI | этот спек |
| 1 | Библиотека колод: много колод, редактор карточек, экспорт/импорт | позже |
| 2 | Режимы тренировки: тест, подбор пар, ввод с клавиатуры, аудирование | позже |
| 3 | Классный режим: проектор, команды, счёт, таймер | позже |
| 4 | Фаза 2: бэкенд, аккаунты, ученики занимаются дома | позже |

**Аудитория Этапа 0** — преподаватель китайского языка, который открывает приложение
на уроке (ноутбук, проектор) и ведёт занятие. Ученики ничего не устанавливают и не
регистрируются.

## Цель этапа

На выходе — приложение с тем же набором возможностей, что и сейчас, но:

- на карточке три поля (иероглиф / пиньинь / перевод) вместо двух;
- направление вопроса выбирается перед тренировкой;
- код разделён на слои, логика типизирована и покрыта тестами;
- приложение открывается по ссылке и работает без сети (PWA);
- каждый коммит проверяется в CI и автоматически публикуется.

Пользовательской новизны здесь почти нет намеренно. Этап 0 оплачивает
технический долг, который иначе умножится на каждом следующем этапе.

## Архитектура

Три слоя с жёсткой границей между ними.

```
src/
  core/            чистая логика, без DOM и без React
    parse.ts       разбор вставленной таблицы в карточки
    pinyin.ts      нормализация пиньиня
    deck.ts        типы карточек, разбиение на блоки
    session.ts     машина состояний тренировки
    storage.ts     сериализация и версионирование схемы
    id.ts          генерация идентификаторов карточек
  state/
    appReducer.ts  редьюсер, вызывающий функции core
    AppContext.tsx провайдер состояния и диспетчера
  screens/
    ResumeScreen.tsx
    ImportScreen.tsx
    ModeScreen.tsx
    TrainingScreen.tsx
    DoneScreen.tsx
  components/
    Card.tsx
    SimpleProgress.tsx
    RingProgress.tsx
    Counters.tsx
    UpdatePrompt.tsx
  hooks/
    useSwipeGesture.ts
    usePersistence.ts
  styles/
  App.tsx
  main.tsx
```

**Правило, определяющее этап:** `core` не импортирует ничего из React и не обращается
к `window`, кроме как в `storage.ts`, где доступ к `localStorage` передаётся параметром.
Слой представления не содержит правил тренировки — он только показывает состояние
и отправляет действия.

Это правило и есть то, ради чего делается Этап 0. Оно позволит на Этапе 4 заменить
локальное хранилище на серверное, не трогая логику тренировки.

Управление состоянием — `useReducer` плюс Context. Redux, Zustand и прочие внешние
стор-библиотеки не используются: состояние маленькое, а функции `core` уже возвращают
новые объекты, что и требуется редьюсеру.

## Модель данных

```ts
type Card = {
  id: string;
  hanzi: string;
  pinyin: string;      // может быть пустой строкой
  translation: string;
};

type Direction =
  | 'hanzi-to-translation'
  | 'translation-to-hanzi'
  | 'hanzi-to-pinyin';
```

`id` генерируется при импорте через `crypto.randomUUID()`; если метод недоступен,
используется запасной вариант из `Math.random()` и счётчика. Идентификатор нужен уже
сейчас: очереди сессии хранят идентификаторы, а не объекты карточек, и React использует
их как ключи списков.

Тип `Deck` на этом этапе не вводится. Колода ровно одна, и обёртка вокруг массива
карточек была бы спекуляцией — она появится на Этапе 1 вместе с библиотекой.

### Что показывает карточка

| Направление | Лицевая сторона | Обратная сторона |
|-------------|-----------------|------------------|
| `hanzi-to-translation` | иероглиф | пиньинь (если есть) и перевод |
| `translation-to-hanzi` | перевод | иероглиф и пиньинь (если есть) |
| `hanzi-to-pinyin` | иероглиф | пиньинь крупно, перевод мелко |

Если ни у одной карточки колоды нет пиньиня, направление `hanzi-to-pinyin`
недоступно: кнопка выключена и рядом стоит пояснение «в колоде нет пиньиня».

## Импорт таблицы

### Определение разделителя

Разделитель определяется по первой непустой строке в порядке: табуляция, точка с
запятой, запятая. Табуляция проверяется первой, потому что переводы часто содержат
запятые, а вставка из таблицы даёт именно табуляцию.

### Определение колонок

Переключатель на экране импорта с тремя значениями:

- **Авто** (по умолчанию) — приложение решает само по правилу ниже;
- **Иероглиф + пиньинь + перевод** — вторая колонка всегда пиньинь;
- **Иероглиф + перевод** — пиньиня в таблице нет.

Правило автоопределения применяется к каждой строке отдельно. Если колонок ровно две,
это иероглиф и перевод. Если три и больше, вторая колонка считается пиньинем тогда и
только тогда, когда она состоит исключительно из латинских букв, `ü`, гласных
с тоновыми диакритиками, пробелов, апострофов, дефисов, двоеточий и цифр 0–5.
Наличие кириллицы, иероглифов или любых других символов означает, что это уже перевод.

Решение принимается построчно, а не один раз на всю таблицу, намеренно: в таблицах из
учебника пиньинь часто проставлен не у всех слов, и построчное правило разбирает такую
таблицу целиком вместо того, чтобы сломаться на первой строке без пиньиня.

Такое правило разрешает главную неоднозначность: строка `你好,привет, здравствуйте`
разбирается как иероглиф плюс перевод «привет, здравствуйте», а не как иероглиф,
пиньинь «привет» и перевод «здравствуйте».

Правило остаётся неоднозначным в одном случае: `你好,hello,greeting`, где второй
столбец латиницей может быть и пиньинем, и переводом. Это разрешается не кодом, а
интерфейсом — см. «Превью» ниже и ручной переключатель колонок.

### Склейка лишних колонок

Всё, что осталось после колонки перевода, присоединяется к переводу. Для табуляции
части соединяются пробелом, для запятой и точки с запятой — разделителем и пробелом.

Сейчас такие строки молча отбрасываются, и на реальных таблицах с переводами вида
«привет, здравствуйте» это даёт десятки потерянных карточек.

### Заголовок

Первая непустая строка считается заголовком и пропускается, если её первая ячейка
совпадает с одним из `иероглиф | 汉字 | hanzi | слово | word | term`, а последняя —
с одним из `перевод | translation | значение | meaning`. Сравнение без учёта регистра.

### Пропуск строк

Строка пропускается, если она пустая, если после разбора пуст иероглиф или пуст
перевод, либо если колонка всего одна. Разбор не прерывается. По окончании
показывается сообщение «Добавлено N карточек, пропущено M строк». Если пропущенных
строк нет, вторая половина фразы не выводится.

### Превью

Под полем ввода показывается таблица первых пяти разобранных карточек с подписанными
колонками. Она обновляется при каждом изменении текста и переключателя колонок.
Превью — это то, что делает автоопределение безопасным: преподаватель видит
неправильное разбиение сразу, а не посреди урока.

### Источники

Вставка в textarea и загрузка файла `.csv`, `.tsv`, `.txt` через `FileReader`
(поведение переносится из текущей версии).

## Нормализация пиньиня

Пиньинь приводится к диакритике при импорте, потому что учебники и словари дают его
и цифрами, и значками.

Обрабатывается каждый слог — последовательность букв, за которой может идти цифра
тона. Разделители (пробелы, апострофы, дефисы) сохраняются.

1. `v` и `u:` заменяются на `ü`.
2. Если слог заканчивается цифрой 1–4, цифра убирается и над гласной ставится
   соответствующий знак; цифры 0 и 5 означают нейтральный тон — цифра убирается,
   знак не ставится.
3. Гласная для знака выбирается по стандартному правилу: `a`, если она есть; иначе
   `e`; иначе в сочетании `ou` знак идёт на `o`; в остальных случаях — на последнюю
   гласную слога. Гласными считаются `a`, `e`, `i`, `o`, `u` и `ü`.
4. Слоги без цифры на конце остаются как есть — значит, уже готовый пиньинь
   с диакритикой проходит через функцию без изменений.

Регистр сохраняется: `Ni3` даёт `Nǐ`.

## Машина состояний тренировки

Логика переносится из `deck.js` без изменения правил. Меняются две вещи: очереди
хранят идентификаторы карточек вместо объектов, и добавляется признак финального круга.

```ts
type SimpleSession = {
  mode: 'simple';
  round: number;
  queue: string[];
  nextRound: string[];
  perfectRound: boolean;
  finalRound: boolean;   // true, если это сводный круг после колец
  finished: boolean;
};

type RingSession = {
  mode: 'ring';
  blocks: string[][];
  blockIndex: number;
  queue: string[];
  finished: boolean;
};

type Session = SimpleSession | RingSession;
```

Хранение идентификаторов вместо объектов важно не только для размера localStorage:
в текущей версии одна и та же карточка лежит в состоянии в нескольких копиях, и любое
будущее редактирование карточки рассинхронизирует их.

**Простой режим.** Свайп вправо убирает карточку из очереди круга и кладёт в очередь
следующего. Свайп влево возвращает её в конец текущей очереди и снимает флаг
«идеального круга». Когда очередь пуста: если круг был идеальным — сессия завершена,
иначе начинается следующий круг из отложенных карточек.

**Режим колец.** Колода делится на последовательные блоки по 7 карточек, последний
может быть короче. Свайп вправо убирает карточку из очереди блока, влево — возвращает
в конец. Пустая очередь блока означает переход к следующему. После последнего блока
запускается сводный круг по всей колоде по правилам простого режима с `finalRound: true`.

**Направление** фиксируется в момент старта сессии и не меняется до её конца.

### Счётчики

```ts
type Stats = { known: number; unknown: number };
```

Хранятся в состоянии приложения рядом с сессией, а не внутри неё: сессия при переходе
от колец к сводному кругу заменяется целиком, а счётчики должны пережить этот переход.
Обнуляются при старте новой сессии. В отличие от текущей версии, сохраняются вместе
с состоянием, чтобы перезагрузка страницы не сбрасывала их на ноль.

## Хранилище

Ключ `flashcards.v2`. Формат:

```ts
type StoredState = {
  version: 2;
  cards: Card[];
  direction: Direction;
  session: Session | null;
  stats: Stats;
};
```

Запись выполняется после каждого изменения состояния через единственный модуль
`core/storage.ts`.

При чтении: если ключа нет, если JSON битый, если `version` не равен 2 или структура
не проходит проверку — данные игнорируются и показывается экран импорта. Приложение
никогда не падает из-за содержимого хранилища.

Старый ключ `flashcards.state.v1` не мигрируется и не удаляется. Колода в прототипе
восстанавливается повторной вставкой таблицы за несколько секунд, а код миграции с
прототипа пришлось бы поддерживать бессрочно.

Если запись не удалась — приватный режим браузера, переполнение квоты — приложение
продолжает работать в памяти и один раз за сессию показывает предупреждение
«Прогресс не сохраняется». Молча терять данные нельзя.

## Экраны

Набор экранов тот же, что в прототипе. Активный экран выводится из состояния,
а не хранится отдельным полем.

**Возобновление.** Показывается при запуске, если в хранилище есть незавершённая
сессия. Текст с числом карточек и текущим кругом или блоком. Кнопки «Продолжить»
и «Загрузить новую» (вторая требует подтверждения, так как стирает прогресс).

**Импорт.** Textarea, кнопка загрузки файла, переключатель колонок, превью первых
пяти карточек, сообщение о результате разбора, кнопка «Создать колоду» (выключена
при нуле карточек), ссылка «Отменить» (видна только если колода уже есть).

**Выбор режима.** Заголовок с числом карточек. Переключатель направления из трёх
вариантов. Две кнопки режимов: «Простой просмотр» и «Заучивание кольцами по 7».
Ссылка «Загрузить новую таблицу».

**Тренировка.** Кнопка закрытия, текст прогресса, полоса прогресса для простого
режима или сегменты по блокам для колец, счётчики «знаю» и «не знаю», баннер о смене
круга или блока, карточка, кнопки «Изучать снова» и «Знаю», ссылка на загрузку новой
таблицы.

**Готово.** Итог: число карточек и число пройденных кругов. Кнопки «Начать заново»
и «В меню».

## Внешний вид

Тёмная тема прототипа сохраняется. Меняется типографика и масштабирование —
приложение должно читаться с задней парты через проектор.

Шрифты для иероглифов: `"PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`.
Системные — веб-шрифт для CJK весит мегабайты и сломал бы офлайн-режим.

Размеры задаются от высоты окна:

- иероглиф — `clamp(4rem, 18vh, 12rem)`;
- перевод — `clamp(1.5rem, 5vh, 3rem)`;
- пиньинь — `clamp(1.25rem, 4vh, 2.5rem)`;
- карточка — `min(90vw, 60rem)` на `min(60vh, 34rem)`.

## Жесты и управление

Логика жестов выносится из DOM-склейки в хук `useSwipeGesture`.

- Перетаскивание карточки указателем (pointer events покрывают мышь и тач).
  Во время перетаскивания карточка смещается, наклоняется и подсвечивается: зелёным
  вправо, красным влево. Свайп засчитывается при смещении больше 80 пикселей.
- Стрелки ← и → — эквивалент свайпа.
- Кнопки «Изучать снова» и «Знаю».
- Пробел и Enter переворачивают карточку. В прототипе переворот был только по клику.
- Esc выходит в меню с подтверждением.

Пока идёт анимация ухода карточки, ввод блокируется. Прототип имел здесь состояние
гонки между перетаскиванием и клавиатурой (исправлено коммитом `d971618`);
поведение переносится вместе с исправлением и закрепляется тестом.

Доступность: карточка — элемент с `role="button"` и `tabIndex={0}`; смена карточки
объявляется через область с `aria-live="polite"`; у кнопок есть понятные подписи.

## PWA

`vite-plugin-pwa` с precache всех собранных ассетов. Манифест: имя «Карточки 汉字»,
короткое имя «汉字», `display: standalone`, цвета из тёмной темы, иконки 192 и 512
пикселей плюс maskable.

`registerType: 'prompt'`. Новая версия не подменяет приложение сама: показывается
уведомление «Доступна новая версия» с кнопкой «Обновить». Тихое обновление посреди
урока перезагрузило бы страницу и прервало занятие.

После первого открытия приложение работает без сети полностью.

## Тестирование

**Vitest, слой `core`.** Здесь лежит вся логика, поэтому здесь же основная часть тестов.

- Разбор: табуляция, запятая, точка с запятой; две колонки и три; заголовок есть и нет.
- Автоопределение колонок: кириллица во второй колонке — это перевод; латиница
  с тоновыми знаками — пиньинь.
- Склейка лишних колонок: `你好,привет, здравствуйте` даёт перевод «привет, здравствуйте».
- Пропуск строк: пустые, с одной колонкой, с пустым иероглифом, с пустым переводом;
  счётчик пропущенных.
- Пиньинь: `ni3 hao3` → `nǐ hǎo`; `lv4` → `lǜ`; `nu:3` → `nǚ`; `ma5` → `ma`;
  `xie4xie5` → `xièxie`; уже готовый `nǐ hǎo` не меняется; `Ni3` → `Nǐ`;
  выбор гласной для `hao`, `gei`, `dou`, `liu`.
- Простой режим: свайп вправо и влево, завершение круга, переход к следующему,
  завершение сессии на идеальном круге.
- Кольца: разбиение на блоки, неполный последний блок, переход между блоками,
  запуск сводного круга с `finalRound: true`.
- Хранилище: сериализация и чтение туда-обратно; битый JSON, чужая версия и
  неполная структура дают пустое состояние, а не исключение.

**React Testing Library, экраны.** Дымовые тесты, проверяющие связки, а не детали
разметки.

- Вставка таблицы и нажатие «Создать колоду» ведут на экран выбора режима с верным
  числом карточек.
- Превью обновляется при вводе текста.
- Старт тренировки показывает первую карточку в соответствии с выбранным направлением.
- Свайп вправо показывает следующую карточку и увеличивает счётчик «знаю».
- Состояние, записанное в localStorage, восстанавливается при новом монтировании
  и приводит на экран возобновления.
- Направление `hanzi-to-pinyin` выключено для колоды без пиньиня.

**Playwright, один сценарий.** Вставить таблицу из восьми строк, пройти режим колец
до конца, включая сводный круг, увидеть экран «Готово».

Больше сквозных тестов на этом этапе не пишется. Один нужен потому, что это
единственное, что ловит поломку сборки, путей и регистрации service worker;
остальные дороги в поддержке и дублируют тесты уровнями ниже.

## CI и публикация

GitHub Actions, Node 20.

- На pull request: `lint`, `typecheck`, `test`, `build`.
- На `master`: то же плюс публикация собранного `dist` на GitHub Pages.

Инструменты: ESLint и Prettier с конфигурацией для TypeScript и React,
`tsc --noEmit` для проверки типов. `vite.config.ts` задаёт `base` по имени
репозитория, иначе GitHub Pages отдаст страницу с битыми путями к ассетам.

## Что переносится, что выбрасывается

Переносится: правила разбора и машина состояний (переписываются на TypeScript,
поведение сохраняется), визуальный стиль тёмной темы, поведение жестов вместе
с исправлением гонки.

Выбрасывается: `main.js` целиком, UMD-обёртка `deck.js`, `deck.test.js`
(переписывается на Vitest), `index.html` как рукописная разметка пяти экранов.

## Подготовительные шаги

Оба выполняются до начала работы над кодом.

**Влить `flashcards-implementation` в `master`.** Вся рабочая версия прототипа сейчас
живёт в неслитой ветке в `.worktrees/`. Если не закрыть это сейчас, Этап 0 стартует
от кода, которого формально нет в основной ветке, и прототип будет потерян при
первой уборке worktree.

**Переименовать папку проекта в `hanzi-cards`.** Путь `Карточки для русского`
содержит кириллицу и пробелы, что регулярно ломает инструменты сборки, и название
больше не соответствует содержимому — карточки китайские, а не русские.

## Вне рамок этапа

Перечислено явно, чтобы не расползтись:

- библиотека колод, папки, несколько колод одновременно — Этап 1;
- редактор карточек — Этап 1;
- экспорт и импорт колод файлом — Этап 1;
- тест с вариантами, подбор пар, ввод с клавиатуры, аудирование — Этап 2;
- озвучка и TTS — Этап 2;
- проектор, команды, счёт, таймер, случайный ученик — Этап 3;
- интервальное повторение, история ответов, статистика — не выбрано ни в один этап;
- бэкенд, аккаунты, выдача колод ученикам — Этап 4;
- светлая тема, локализация интерфейса — не планируется.

## Критерии готовности

Этап считается завершённым, когда выполнено всё перечисленное:

1. Приложение открывается по адресу GitHub Pages и устанавливается как PWA.
2. После первого открытия работает при выключенной сети.
3. Таблица в три колонки с пиньинем цифрами импортируется, пиньинь показывается
   с диакритикой.
4. Таблица в две колонки с запятыми внутри перевода импортируется без потерь.
5. Все три направления работают; для колоды без пиньиня третье выключено.
6. Оба режима тренировки проходятся до экрана «Готово», включая сводный круг колец.
7. Перезагрузка посреди тренировки восстанавливает карточку, круг, счётчики
   и направление.
8. `lint`, `typecheck`, `test` и `build` проходят в CI на чистом клоне.
9. `src/core` не содержит ни одного импорта React и ни одного прямого обращения
   к `window` или `document`.
